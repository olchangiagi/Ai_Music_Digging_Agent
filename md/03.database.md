# 03.database — 로컬 PostgreSQL에 곡 데이터 저장

## 목표

02.music_data에서 만든 `Track`을 로컬 PostgreSQL에 영구 저장하고, MusicBrainz ID로 조회하거나 태그로 검색할 수 있게 한다. pgvector 확장을 준비하되 임베딩과 벡터 검색은 이후 단계에서 구현한다.

## 수행한 작업

- Docker Compose로 로컬 PostgreSQL + pgvector 환경 구성
- `.env`의 DB 이름, 사용자, 비밀번호, 포트를 사용하는 설정 작성
- 데이터 유지를 위한 Docker 볼륨 설정
- `vector` 확장과 `tracks` 테이블을 정의하는 SQL 스키마 작성
- `psycopg`를 이용한 DB 연결 함수 작성
- MusicBrainz ID를 기본 키로 사용해 곡을 저장하고, 같은 ID는 갱신하도록 구현
- ID로 곡 한 건을 조회하고, 태그를 대소문자 구분 없이 검색하는 함수 작성
- MusicBrainz·Last.fm으로 만든 `Track`을 DB에 저장하는 수집 함수 작성
- 외부 API와 DB 저장 함수를 모의 처리해 수집 흐름을 검증하는 테스트 작성

## 주요 파일과 역할

| 파일 | 역할 |
|---|---|
| `docker-compose.yml` | 로컬 PostgreSQL + pgvector 컨테이너와 데이터 볼륨 설정 |
| `db/schema.sql` | `vector` 확장 및 `tracks` 테이블 정의 |
| `app/db.py` | DB 연결, 곡 저장·갱신, ID 조회, 태그 검색 |
| `app/ingest.py` | MusicBrainz·Last.fm 데이터 수집과 DB 저장 연결 |
| `tests/test_ingest.py` | 선택한 ID로 만든 `Track`이 저장 함수에 전달되는지 검증 |
| `requirements.txt` | PostgreSQL 접속용 `psycopg[binary]` 의존성 포함 |

## 데이터 구조와 동작

`tracks` 테이블은 `musicbrainz_id`를 UUID 기본 키로 사용한다. 제목, 아티스트, 태그 배열, 구분 설명, 생성 시각을 저장한다.

`save_track()`은 같은 MusicBrainz ID가 이미 있으면 제목·아티스트·태그·설명을 갱신한다. `get_track_by_id()`는 저장된 곡을 `Track`으로 복원하고, `search_tracks_by_tag()`는 태그의 대소문자를 구분하지 않고 검색한다.

`ingest_track_by_id()`는 지정한 ID의 MusicBrainz 정보를 가져오고 Last.fm 태그를 붙인 뒤 PostgreSQL에 저장한다.
