# 02.music_data — 실제 음악 데이터 수집과 결합

## 목표

MusicBrainz에서 실제 곡의 recording 정보를 찾고, Last.fm에서 태그를 가져와 공통 `Track` 모델로 결합한다. 같은 제목·아티스트의 검색 결과가 여러 개일 때 첫 번째 결과를 자동 선택하지 않고, MusicBrainz ID로 사용할 후보를 명확히 지정한다.

## 수행한 작업

- MusicBrainz recording 검색과 ID 직접 조회 기능 작성
- 제목, 아티스트, 길이, 발매 정보, 구분 설명, ID를 확인하며 후보 비교
- 지정한 ID가 검색 후보에 있으면 해당 recording을 선택하고, 없으면 `ValueError`를 반환하도록 구현
- MusicBrainz 응답을 `Track`으로 변환하고, 빈 구분 설명은 `None`으로 통일
- Last.fm `track.getTopTags`로 태그를 요청하고 태그 이름만 추출
- 선택한 recording의 제목·아티스트로 태그를 조회해 `Track.tags`에 연결
- `Track` 한 개를 JSON 파일로 저장하고 다시 읽어 복원되는지 확인
- ID 선택 로직의 정상 선택·없는 ID 처리에 대한 단위 테스트 2개 작성

## 주요 파일과 역할

| 파일 | 역할 |
|---|---|
| `app/musicbrainz.py` | recording 검색, ID 조회, MusicBrainz 응답의 `Track` 변환 |
| `app/lastfm.py` | 곡 태그 요청, API 오류 확인, 태그 이름 추출 |
| `app/music_data.py` | 후보 검색·ID 선택과 두 API의 데이터 결합 |
| `app/models.py` | 제목, 아티스트, 태그, MusicBrainz ID, 구분 설명을 담는 `Track` 모델 |
| `app/catalog.py` | 샘플 곡 목록 로딩 및 단일 `Track` JSON 저장·읽기 함수 |
| `data/midnight_city_m83.json` | 실제 API 데이터로 만든 단일 곡 JSON 예시 |
| `tests/test_music_data.py` | ID 기반 후보 선택 로직의 단위 테스트 |
